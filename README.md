# Финансовый учёт

Быстрый, приватный офлайн-трекер личных финансов. Все данные хранятся локально в браузере
(`localStorage`) и никуда не отправляются. Приложение работает как устанавливаемый PWA: его можно
добавить на главный экран телефона и пользоваться без интернета.

## Возможности

- **Обзор** — сводка за текущий месяц: сколько потрачено сегодня, доходы, расходы, баланс (с
  примерным эквивалентом в рублях), прогресс общих бюджетов (на месяц и на неделю) и бюджетов категорий, которые
  подходят к лимиту, среднее и медиана трат в день. Графики — в Аналитике.
- **Операции** — список по дням (заголовок дня прилипает при прокрутке) с поиском по категории,
  заметке или сумме, фильтрами и сортировкой. На телефоне операция удаляется свайпом влево, на компьютере —
  кнопкой с подтверждением. После удаления можно нажать «Отменить».
- **Форма операции** — сумма (с эквивалентом в рублях прямо под ней) и категория (недавние и частые
  первыми). Дата («Сегодня» / «Вчера» / календарь), заметка и «Повторять каждый месяц» — в свёрнутом
  блоке «Дополнительно», строка под заголовком показывает, что выбрано. «Повторить сегодня» — для
  повторяющихся трат. Если расход довёл бюджет до 80% или 100%, об этом скажет уведомление.
- **Регулярные операции** — галочка «Повторять каждый месяц» при добавлении: аренда, зарплата,
  подписки добавляются сами в тот же день каждого месяца (31-е в коротком месяце — последний день).
  Пропущенные месяцы, пока приложение не открывалось, добавляются при следующем запуске, без дублей.
  Список и остановка повтора — в Настройках.
- **Аналитика** — любой период (сегодня, 7 дней, месяц, год, свой диапазон), сравнение с предыдущим
  периодом, самый дорогой и самый дешёвый день, графики. Выбранный период хранится в адресе
  (`#/analytics?period=lastMonth`), поэтому не сбрасывается при переходах и кнопке «Назад» и
  переносится в Операции при нажатии на категорию.
- **Настройки** — тема (светлая / тёмная / системная), бюджеты на месяц и на неделю (общие и по категориям),
  регулярные операции, категории, PNG-отчёт за период, экспорт и импорт JSON (вместе с заметками и
  регулярными операциями), экспорт CSV.
- **Офлайн** — после первой загрузки все разделы открываются без сети.
- **Обновления** — когда на сервере появилась новая версия, сверху появляется плашка «Доступна новая
  версия · Обновить». Приложение переключается только по нажатию, поэтому не перезагрузится посреди
  ввода операции. Одинаково на Android, iOS и компьютере; открытое приложение проверяет обновления
  раз в час и при возвращении на экран.

## Запуск проекта

```bash
npm install
npm run dev       # сервер разработки: http://localhost:5173/finance-tracker/
npm run build     # проверка типов + production-сборка в dist/
npm run preview   # production-сборка локально: http://localhost:4173/finance-tracker/
npm test          # тесты (Vitest)
npm run lint      # линтер (oxlint)
```

В режиме `npm run dev` service worker не работает, поэтому офлайн-режим и установку PWA проверяйте
через `npm run build && npm run preview` (в Chrome DevTools → Application → Service Workers).

Чтобы открыть preview с телефона в той же Wi-Fi сети: `npm run preview -- --host`.

## Деплой и ветки

- **Production — Vercel, только из ветки `main`.** На Vercel приложение собирается с базовым путём `/`,
  локально и в остальных окружениях — с `/finance-tracker/` (см. `vite.config.ts`).
- Новые изменения делаются в ветках `feature/*` и попадают в `main` только после проверки.
- **GitHub Actions:**
  - `Feature CI` — на каждый push в `feature/**` и на pull request в `main`: `npm ci`, lint, тесты, сборка;
  - `Build and Deploy` — на push и pull request в `main`: те же проверки и сборка для GitHub Pages.

Маршрутизация — `HashRouter` (адреса вида `/#/transactions`), поэтому дополнительная настройка
SPA-маршрутов на хостинге не нужна.

## Архитектура

- **`src/lib/storage.ts`** — единственный модуль, который работает с `localStorage`. Остальная
  часть приложения использует его через хуки, поэтому слой хранения можно заменить без переписывания UI.
- **`src/lib/recurring.ts`** — чистая логика регулярных операций: даты повторов и догоняющее
  добавление с детерминированными id (`<правило>@<дата>`), поэтому две вкладки не создадут дубли.
- **`src/lib/calculations.ts`** — чистые функции финансовых расчётов: доходы, расходы, баланс,
  среднее и медиана, разбивка по категориям, прогресс бюджетов и т. д.
- **`src/lib/date-utils.ts`** — календарные даты без часовых поясов. Даты операций хранятся как строки
  `yyyy-MM-dd`.
- **`src/lib/exchangeRate.ts`** — курс VND → RUB только для отображения (кеш на 12 часов,
  без сети — последний сохранённый или примерный курс).
- **`src/hooks/`** — хуки для областей данных (`useTransactions`, `useCategories`, `useBudgets`,
  `useSettings`, `useRecurring`) и вспомогательные хуки.
- **`src/context/AppDataContext.tsx`** — общее состояние приложения, чтобы все страницы работали
  с одними и теми же данными.
- **`src/i18n/`** — все строки интерфейса (сейчас русский язык).
- **`src/components/`** — компоненты по функциональности: `transactions/`, `categories/`, `budgets/`,
  `dashboard/`, `analytics/`, `period/` (выбор периода), `settings/`, `layout/` и базовые компоненты
  в `ui/`.
- **Контексты** отдают стабильные значения: открытие формы операции или показ toast не
  перерисовывают текущую страницу целиком.

### Загрузка и офлайн

- **Первый экран грузится быстро.** Обзор входит в основной бандл. Остальные разделы и графики
  (Recharts) вынесены в отдельные чанки и подгружаются по мере необходимости, а после первой
  отрисовки — заранее, в фоне (`src/lazyPages.ts`, `src/lib/lazyWithPreload.tsx`).
- **Без пустых экранов.** Пока раздел загружается, навигация остаётся на месте и показывается
  заглушка. Если раздел не удалось загрузить без сети, показывается понятное сообщение с кнопкой
  «Повторить» (`ChunkErrorBoundary`); при появлении сети повтор происходит автоматически.
- **Экран запуска** встроен прямо в `index.html` и появляется в первом же кадре, ещё до загрузки
  JS и CSS. Тема определяется до отрисовки, поэтому в тёмной теме нет белой вспышки.
- **PWA** — `vite-plugin-pwa` (Workbox) кеширует все файлы сборки; установленное приложение
  открывается и работает без сети. Service worker регистрируется в режиме `prompt`
  (`src/pwa/registerServiceWorker.ts`): новая версия скачивается в фоне и ждёт нажатия «Обновить»
  (`src/pwa/appUpdate.ts`, `UpdateBanner`). Без поддержки service worker приложение просто работает
  онлайн. Иконки: SVG и PNG (192, 512, maskable) в манифесте, `apple-touch-icon.png` для iOS;
  цвет строки состояния (`theme-color`) следует теме приложения.
- **Переход с версий до 1.5.** Старая версия обновлялась автоматически и не умеет показывать плашку,
  поэтому первое обновление до 1.5 применится после полного закрытия приложения (все вкладки /
  выгрузить из многозадачности) и повторного открытия. Дальше — через плашку.

## Основные решения

- **Валюта:** все суммы хранятся и считаются только в VND (₫), целыми числами, не больше
  999 999 999 999 ₫. Рубли показываются только как примерный эквивалент в карточках сводки и нигде
  не сохраняются.
- **Расчёты за период** делаются за один проход (`summarize` в `src/lib/calculations.ts`).
  Среднее в день считается только по уже прошедшим дням: 24 сентября «Этот месяц» делится на 24 дня,
  а не на 30. Медиана в день — по дням, в которые были траты («сколько уходит в обычный день с
  тратами»): дни без трат её не обнуляют. Сравнение с прошлым периодом тоже берёт равный отрезок: 1–24 сентября
  против 1–24 августа.
- **Хранение:** данные находятся только в браузере пользователя. Бэкенда, аккаунтов и синхронизации
  между устройствами нет. Открытые вкладки (и установленное приложение рядом с вкладкой браузера)
  видят изменения друг друга сразу.
- **Резервная копия:** данные можно экспортировать в JSON и восстановить из резервной копии. Файл
  полностью проверяется до записи, а запись идёт по принципу «всё или ничего»: если что-то не
  получилось (например, не хватило места), текущие данные остаются нетронутыми.
- **Экспорт:** операции выгружаются в CSV (разделитель `;` и UTF-8 с BOM — Excel с русскими
  настройками сразу раскладывает столбцы), отчёт за выбранный период — в PNG (через `html-to-image`,
  библиотека загружается только при генерации отчёта). Имя отчёта говорит о периоде:
  `report-2026-09.png`. На телефонах файлы сохраняются через системное меню «Поделиться» (если
  браузер умеет делиться файлами), на компьютере — обычной загрузкой.
- **Смена дня:** если приложение открыто через полночь, «Сегодня» и «Этот месяц» переключаются сами
  (и при возвращении в приложение).
- **Идентификаторы** создаются и без `crypto.randomUUID`, поэтому приложение работает и по обычному
  http в локальной сети (`npm run preview -- --host`).
- **Графики:** Recharts.
- **Бюджеты:** на месяц или на неделю (пн–вс), общий или для категории; месячный и недельный
  можно держать одновременно, один бюджет на пару «категория + период». Бюджеты без периода
  (созданные до 1.6) считаются месячными. Уведомление 80% / 100% считает каждый бюджет в его периоде.
- **Удаление категории:** если категория используется, её операции сначала нужно переназначить на
  другую активную категорию того же типа. Операции автоматически не удаляются, а бюджет этой
  категории удаляется вместе с ней.
- **Удаление операции:** свайп влево на телефоне (удаляет после порога, с отменой через toast),
  кнопка с подтверждением на компьютере.
- **Мобильный ввод:** форма операции подтверждается клавишей Done/Enter на экранной клавиатуре.
- **Анимации** короткие и чёткие (только `transform` / `opacity`, в основном 100–250 мс, без
  длинного медленного «хвоста»), без новых зависимостей:
  - смена вкладки — вкладка подсвечивается и иконка «вдавливается» в момент касания, ещё до смены
    страницы; новая страница появляется сразу с проявлением 120 мс, которое не блокирует нажатия;
    индикатор переезжает за 150 мс (`src/components/layout/tabTransition.ts`). В 1.5 здесь была
    анимация через View Transitions API: на ~400 мс она замораживала экран и нажатия, и на Android
    переход ощущался вязким — в 1.6 её убрали;
  - числа в сводке доезжают до нового значения за 250 мс после добавления или удаления операции
    (при открытии экрана — сразу на месте);
  - карточки Обзора появляются по очереди только при первом открытии приложения; Аналитика мягко
    проявляется при смене периода;
  - полоса бюджета заполняется при первом показе за запуск (400 мс), дальше меняется за 250 мс и
    меняет цвет на 80% / 100%; столбики графика вырастают при первом показе;
  - удалённая операция складывается, возвращённая через «Отменить» — раскрывается, новая коротко
    подсвечивается; на Android при свайпе чувствуется лёгкая вибрация.

  Всё через проверку поддержки (`element.animate`, `navigator.vibrate`): без неё приложение
  работает как раньше, просто без эффекта. Системная настройка «Уменьшить движение» отключает
  анимации.

## Тестирование

`npm test` запускает тесты Vitest (jsdom). Они покрывают:

- финансовые расчёты: доходы, расходы, баланс, среднее (по прошедшим дням) и медиана (по дням с тратами),
  категории, самый дорогой и дешёвый день, сравнение с прошлым периодом, пороги бюджетов;
- резервные копии: экспорт и повторный импорт, отклонение повреждённых файлов, запись «всё или
  ничего», удаление бюджета вместе с категорией, лимит суммы;
- подготовку данных графика расходов (выбросы, пустые и нулевые данные);
- курс рубля: форматирование, кеш, работу без сети, отсутствие параллельных запросов;
- список операций: свайп (следование за пальцем, порог, сопротивление, возврат, отсутствие случайного
  открытия), удаление на компьютере с подтверждением, удаление именно нужной операции;
- загрузку разделов: заглушку при загрузке, сообщение при ошибке, повторную попытку;
- экспорт: CSV для Excel, имена файлов отчёта, «Поделиться» на телефоне и загрузку на компьютере;
- фильтр операций по архивной или удалённой категории, смену дня при открытом приложении;
- форму операции (рубли, быстрые даты, заметка, «Повторять каждый месяц», «Повторить сегодня»),
  порядок категорий, поиск по сумме и заметке, предупреждения о бюджете;
- регулярные операции: короткие месяцы, догоняющее добавление без дублей, резервные копии, удаление
  и перенос категории;
- плашку новой версии, `theme-color` по теме, анимации (с поддержкой API и без неё);
- бюджеты на Обзоре и недельные бюджеты, период в адресе страницы, синхронизацию между вкладками;
- экран запуска, сброс прокрутки при смене вкладки, отсутствие выбора периода на Обзоре.

Перед отправкой изменений запускайте:

```bash
npm run lint
npm test
npm run build
```

### Проверки перед релизом (в настоящем браузере)

Сценарии Playwright в `scripts/` гоняют production-сборку в Chromium на экране телефона. Нужны
Playwright и Chromium (`npm i -D playwright && npx playwright install chromium`, в зависимости
проекта не входят).

```bash
npm run build && npx vite preview --port 4174 &
node scripts/e2e-calendar.mjs   # полночь при открытом приложении, 31.12 → 1.01, 29.02, регулярные на 31-е
node scripts/e2e-network.mjs    # офлайн, раздел не в кеше, медленный 3G, обрыв при загрузке
node scripts/e2e-data.mjs       # две вкладки, CSV, импорт битых копий, двойной тап, длинные названия
node scripts/e2e-budgets.mjs    # бюджеты на месяц и неделю, уведомление 80%, сброс в понедельник
node scripts/perf.mjs 5000      # скорость на 5 000 операций при процессоре, замедленном в 4 раза
node scripts/e2e-update.mjs     # обновление PWA (правит dist/ — после него пересоберите)
```

## Текущая версия

**V1.5.1** — стабилизация: понятное сообщение, если данные не удалось сохранить; повреждённые
данные в хранилище больше не роняют приложение; подсказка, когда нет категорий; длинный список
операций рисуется порциями (5 000 операций — без задержек), поиск не тормозит ввод; «Сначала
старые» действительно начинается со старых дней; двойной тап не добавляет операцию дважды;
восстановление после обрыва сети при загрузке; баланс в PNG-отчёте окрашен по знаку.

**V1.5** — заметки и регулярные операции, бюджеты на Обзоре, период в адресе, синхронизация
вкладок, плашка новой версии, анимации, исправления экспорта, импорта и расчётов. Версия 1.0 —
предыдущая стабильная.

Приложение рассчитано на локальное личное использование. Слой хранения изолирован, чтобы в будущем
можно было добавить синхронизацию и другие интеграции без переделки бизнес-логики и интерфейса.
